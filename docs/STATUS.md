# Cloudy Cloud: what is built, and what has been proven

As of 2026-11-17 (agent support), 2026-11-11 (rest). **"Proven live"** means it was run against real Instabox machines, a real Claude login and real GitHub, and the result was checked on GitHub or Instabox, not taken from an agent's reply.

Provider interface refactor (2026-11-10): provider selection uses `CLOUDY_CLOUD_PROVIDER` (`instabox`, the default, or `self-hosted`). `install.sh` asks which one, and `cloudy-cloud setup --provider` skips the question. See [sandbox provider research](research/sandbox-providers.md).

## Supported agents and what is proven

Main sessions (the agent you talk to) and workers (the agent on each cloud machine) are chosen independently. Coordinators always run Claude Code, and refuse pi, omp, Codex and opencode profiles. The branch `feat/multi-agent` merges the Codex, opencode and pi host branches (87d7503); nothing is pushed yet.

| Agent | As main session | As worker (profiles) | Status |
|---|---|---|---|
| Claude Code | `cloudy-cloud` | default; `glm`, `deepseek`, `particle`, `openrouter` | Main session: verified live. Worker: verified live |
| pi | `cloudy-cloud pi` | `pi-glm`, `pi-deepseek`, `pi-particle` | Main session: partly verified (MCP connection only, no model turn). Worker: verified live |
| oh-my-pi | none | `omp-glm`, `omp-deepseek`, `omp-particle` | Worker: verified live (follow-ups by unit tests only) |
| Codex | `cloudy-cloud codex` | `codex`, `codex-chatgpt`, `codex-openrouter` | Main session: partly verified (it listed the six cloud tools with codex-cli 0.166.0; no worker was started from it). Worker: not verified on a real machine (fake-sandbox tests only) |
| opencode | `cloudy-cloud opencode` | `opencode-glm`, `opencode-deepseek`, `opencode-particle`, `opencode-openrouter` | Main session: verified live. Worker: not verified on a real machine (fake-sandbox tests only) |
| free-pi | `cloudy-cloud free-pi` | none (blocked: no headless mode, and its terms forbid it) | Main session: partly verified (`mcp list` only) |

**This table is the single source for these statuses.** Other pages link here and use the same three terms: "verified live" (run on a real machine and the result checked), "partly verified" (a named check only) and "not verified on a real machine" (tests with a fake sandbox only). The same terms apply to self-hosted: no Codex, opencode, pi or omp worker has run there.

Credentials: Claude Code workers use the Claude token or API key; pi, omp and opencode profiles use `PARTICLE_API_KEY` (opencode also `OPENROUTER_API_KEY`); `codex` uses `OPENAI_API_KEY`; `codex-chatgpt` uses `~/.config/cloudy-cloud/codex-auth.json`; the OpenRouter profiles use `OPENROUTER_API_KEY`. Setup asks for the Claude token only if claude is chosen, the OpenAI key if codex is chosen, and the Particle.ai and OpenRouter keys. The integrated suite on 2026-11-17 had 930 tests: 928 passed, 1 failed (`a plain worker without mcp.json runs the same claude command`, an old expectation about the `mcp.json` fallback, failing the same way before the merge), 1 skipped. No live run was made after the merge.

## What it is

`cloudy-cloud` starts Claude Code with every subagent running on its own Instabox cloud machine.
- **Pushing:** each subagent works on branch `cloudy-cloud/<id>`, and commits and pushes its own work to the repo's GitHub origin.
- **Agents and models:** subagents can run Claude Code, pi, oh-my-pi, Codex or opencode, on Claude or on open models such as GLM and DeepSeek through Particle.ai or OpenRouter, or OpenAI models through Codex. The main session can be Claude Code, Codex, opencode, pi or free-pi.
- **Coordinators:** a coordinator, nested inside a session or long-lived in the cloud, can run its own fleet and merge the work into one branch.

## Bugs found by live runs, all fixed with regression tests

- **Wrong branches:** commits landed on other agents' branches under load, caused by a shared `FETCH_HEAD`. The copy-back was later removed entirely in favour of agents pushing their own branches.
- **Leaked token:** an exported `ANTHROPIC_API_KEY` was removed by the cmux wrapper, so the sandbox wasn't logged in.
- **Orphaned machines:** sessions that ended left machines behind. Fixed by the cleanup process.
- **Early endings:** workers put long commands in the background, so their tasks ended early. Fixed with `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`, plus a 28-minute Bash timeout.
- **Lost waits:** a single Instabox request timeout killed a healthy job. Waits now retry.
- **Push failures:** GitHub rejected 1 push in 100 during a mass first push. First pushes now retry, and the token hint appears only for auth errors.
- **LiteLLM gateway:** it needed a master key, and it routed requests to the Responses API, which Particle lacks (405). Fixed in config.
- **Misleading cost:** open-model results showed Anthropic-priced costs. The cost is now hidden for them.
- **Coordinator tool version:** cloud and nested coordinators get the laptop's exact cloudy-cloud (a git bundle of HEAD plus uncommitted tracked edits), not a clone of GitHub. The tool repo no longer needs to be pushed or reachable by `GH_TOKEN`. Covered by unit tests only; not yet run against a live machine.
- **Coordinator setup:** `tmux` was missing and the package lists were empty; `gh auth setup-git` ran after the clone; Claude Code's first-run screens blocked Remote Control. All fixed.
- **Skill gap:** the fleet skill switched the user's own folder's branch. It now uses a worktree.
